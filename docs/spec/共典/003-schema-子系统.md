# 003 · schema 自动生成子系统：识别信号、表达形态、验证与版本化

> **来源**：[GitHub #4 解法评论](https://github.com/YunxiLuna/TRPGTogether/issues/4)（方式：grilling 2 轮 + 子代理世界书信号调研，浅参考 `data/input` 两份 docx，调研报告 [prototype/worldbook-signal-survey.md](../../prototype/worldbook-signal-survey.md)）。
>
> **为什么（人类可读）**：本票攻坚简报 A 题（最高优先级）——从任意世界书自动生成轻量 schema 与计算引擎的完整机制。核心设计=**两层漏斗识别**（确定性启发式定位不用 LLM + LLM 解读起草）+ **YAML 6 基元表达**（固定 6 基元=防 schema 膨胀第一道闸）+ **三级锚依据引用** + **自洽→回算→交叉(007 门控)→回归四段验证流水线** + **状态投影版本化 + 双门槛升级判定**（防膨胀第二道闸）。下游 004/007/008/009 全部站在这套机制之上。

## Q1 识别信号机制与阈值（两层漏斗 + 三档置信度）

- 第一层确定性启发式定位（不用 LLM）：token 规则扫候选区——等号/上限 token、稳定列头伪表格、一行色阶链、`x/N` 计数。便宜、可复现、不引入 LLM 找漏。
- 第二层 LLM 解读定位出的区域，起草 schema 并打置信度。
- 置信度 = 结构信号强度 × 语义消费度 × 定义一致性。
  - **结构**：显式公式 > 稳定列头伪表 > 藏在叙事里的计数/状态机。
  - **消费度判据（细化）**：被"规则/公式实际消费"才算高（气运±5%、悟性每 50 点 +1%）；仅被"叙事提及"或无消费公式=低（魅力 1~100 无 +X% 规则吃它）。
  - **一致性**：同量多处定义且用词一致=高；重复且矛盾（如魂环色 3.3 vs 15.2）=降档。
- **三档阈值**：高置信→自动建；中置信→建但标"低置信/需回算"；低置信（纯叙事或无消费公式）→不建，保持自然语言。

## Q2 表达形态（YAML 声明式 + 6 基元 + 量纲唯一多出处）

- YAML 序列化的声明式规则文法，解释器为通用执行器（002 S3：结算权威=声明式解释器）。
- **6 基元**（固定，防膨胀第一道闸）：
  - `quantity{name, unit, range{min,max}, cap?, values?, enum?, conversion?{ratio|unknown}}`
  - `mapping{from → {to, rarity?, color?, grade?}}`
  - `formula`（对 quantity 的表达式 + 运算符 + cap）
  - `state_machine{states, transitions{from, to, guard, probability?}}`
  - `event_hook{on(quantity >= threshold) → trigger}`
  - `progress{counter, target → unlock}`
- **量纲唯一 + 多出处**：一个 quantity 只定义一次（canonical），带 `citations[]` 引用多个世界书片段（见 Q3）。

## Q3 依据引用形态（三级锚）

- `citations[]` 每项：`{section（章节锚，人读）, para_hash（归一化段落短哈希，机读稳定跨再提取）, prefix（原文前 ~50 字，肉眼定位）}`。
- schema 元素 `citations[]` 指向所有出现处（canonical 一条 + 佐证/冲突若干条）。

## Q4 自动验证流水线（自洽 → 回算 → 交叉(007 门控) → 回归）与失败映射

- 顺序：①**自洽检查**（纯结构：映射是函数、区间满足 cap、状态机无不可达态、同输入不出两值）零成本先跑；②**回算**（用世界书内已知算例跑引擎比对，如装逼值 500×1.5×2=1500）；③**多模型交叉**（可选增强，007 校准门控，非标准路径）；④**叙事历史回归**（要等剧情积累，放最后）。
- 失败映射：
  - 自洽失败→**回滚**整个 schema 重生成；
  - 回算失败在某规则→**隔离**该规则（标低置信，该量退回自然语言）；
  - 回算发现世界书内部自相矛盾→**标传闻**（取先写/主源为正典，冲突处记 `canon:false + reason`，相关方收角色内视角传闻，对齐 002 账本层仲裁）；
  - 回归失败→走 Q5 版本化路径**自动修正 + 版本升级**，若破坏已结算状态则经迁移规则投影，不硬改旧账本。

## Q5 版本化迁移策略 + 新属性升级判定

- **Q5a 状态投影 + 版本标签账本条目**，不动账本本体：账本 append-only 是事实源，schema 是"视图"。v1→v2 写一条迁移规则（旧字段→新字段）入账本；旧状态读时由迁移规则投影到新版；每条账本条目带 `schema_version` 标签，未触及字段按旧版语义读。不选兼容层双轨（两套解释器贵），不选账本重放（append-only 不便重写）。
- **Q5b 双门槛升级判定**（与 Q1 同一判据）：新属性（如剑意值）同时满足 ①被至少一条产生量化结果的公式/规则实际消费（"剑意值超过 X 才能使出 Y"）且 ②剧情已确认它是承重量（非路过形容），才升级为 schema；只"提到"而无消费公式→保持自然语言。增量升级只动这一个属性 + 它的消费规则（局部非全量），是防膨胀的第二道闸。**承重量门槛与 007 校准机制挂钩，N 与权重由 007 定**（见 [007 § 落地 map 的 4 条雾](./007-自动校准与漂移纠偏.md#落地-map-的-4-条雾)）。

## 3 个 schema 示例骨架（票面要求）

- **明确体系**：修仙"突破成功率"（第三卷·4.3 总成功率=丹药基础+强行加成×50%、上限 15%/95%）→ `formula` + `quantity(cap)` + `state_machine`（三路径突破 + 4 级失败终态）。完整 YAML 见 [schema-示例.md 示例 1](./schema-示例.md#示例-1--修仙突破成功率来自世界书明确体系)。
- **剧情增量**：玩家自创"剑意值"→ 双门槛满足时建 `quantity{剑意值}` + `formula`（消费它的那条规则），局部增量。完整 YAML 见 [schema-示例.md 示例 2](./schema-示例.md#示例-2--剑意值剧情增量生成)。
- **反例**：修仙"气运"（有 1~100 范围但实际消费是 ±5%/翻倍档位语义，无精算整数消费）→ 不建 int 列，存 `narrative_role:"luck"` 或 高/中/低 枚举，保持自然语言档位。完整 YAML 见 [schema-示例.md 示例 3](./schema-示例.md#示例-3--气运反例保持自然语言档位不建-int-列)。

## 放弃项（下游统一假设升级为：声明式 schema(YAML 6基元) + 解释器结算 + 账本层仲裁 + 自洽→回算→交叉(007门控)→回归 四段流水线 + 状态投影版本化 + 双门槛升级判定）

- 自定义 DSL（冷启动成本高、LLM 生成可靠度低于 YAML）；
- JSON 作 schema 载体（比 YAML 啰嗦）；
- 多模型交叉作标准路径（002 已降级为 007 门控的可选增强）；
- 兼容层双轨 / 账本重放（贵、不便）；
- 单行号或单哈希作依据引用（各自缺陷，三级锚各管一头）。
