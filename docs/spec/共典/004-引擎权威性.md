# 004 · 引擎权威性与冲突仲裁

> **来源**：[GitHub #5 解法评论](https://github.com/YunxiLuna/TRPGTogether/issues/5)（方式：grilling 1 轮，5 题全按推荐拍板）。
>
> **为什么（人类可读）**：本票攻坚简报 B 题——"引擎输出不可被叙事层随意覆盖"到底靠什么机制兜住。核心设计=**引擎是唯一结算权威（单向结算写者）**，叙事层没有写进"已结算值"的物理路径（结构性保证，非运行时仲裁）。三例外模式（世界书矛盾→隔离态 / 规则外→无结算 / 验证失败→suspect 标签）都不是"叙事覆盖引擎"，而是"引擎暂停/不给结算"。两人矛盾仲裁发生在**账本层**（先提交正典/后提交旁支），不是引擎层。

## Q1 权限边界 — 引擎是否绝对优先

- 引擎是**唯一结算权威**（002 决议②）：叙事 LLM 只能提议数值，无权改写引擎输出。引擎输出"不可被叙事层覆盖"靠**结构性保证**（见 Q4 机制载体），不是靠运行时仲裁。
- "绝对优先"需加一层 nuance：引擎的职责是**结算**（给定输入算结果），不是**裁决行动有效性**或改写叙事。引擎可进入三种"例外模式"，每种都不是"叙事覆盖引擎"，而是"引擎暂停/不给结算"：
  - **例外 1 世界书自相矛盾**（Q2 范围）：引擎在生成/回算时发现同量纲双值 → 该量纲进入**隔离态**（quarantine），不给结算输出；双值都写账本，主源（消费公式数最多）`canon:true`，争议值 `canon:false + reason_code: worldbook_conflict`。相关方/缺席者收角色内视角传闻（接 002 决议③、005 谣言机制）。
  - **例外 2 规则外情况**（Q3 范围）：属性不在 schema 里 → 引擎**没有该属性的结算输出**（不存在"覆盖"，根本没结算）；属性保持自然语言（`narrative_role`），叙事自由。一旦被 003 Q5b 双门槛升级，引擎接管结算。
  - **例外 3 引擎验证失败期**（003 Q4 回算/回归失败）：该 schema 版本标 `suspect`，窗口内的结算输出带 suspect 标签，下游**不静默信任**；是"隔离模式"而非"叙事覆盖"。
- 一句话：**引擎是单向结算写者，叙事层没有写进"已结算值"的路径**。

## Q2 世界书矛盾 — 主源选择算法

- 不选章节序/先写（人工判断启发式，违反"无人审"约束，且会误把"被规则反复引用的旧值"判成承重）。
- **主源 = 消费公式数最多者**（被最多结算规则实际使用的值 = 承重值 = 引擎实际在用的那个）；消费数平手时 tie-break 用先写。
- 争议值不静默折叠：保留为 `canon:false + reason_code: worldbook_conflict`，面板上折叠进传闻层（见 Q5 面板呈现）。

## Q3 规则外情况 — 升级判定（复用 003）

- 复用 003 Q5b 双门槛（被公式消费 + 剧情承重量）：门槛满足 → 触发增量 schema 生成（003 流程），007 门控；不满足 → 保持自然语言。判定自动化，不是人工决定。引擎权威性角度：规则外属性"没有引擎结算"是定义性的，叙事自由；一旦升级，引擎接管。

## Q4 并发冲突 — 仲裁机制 + 旁支账本形态

- **结构矛盾**（数值/唯一物归属）：纯**规则引擎**定序——append-only 账本里的 seq/时间戳决定"先提交者正典、后提交者旁支"，机械、可审计、零成本。
- **叙事矛盾**（两件事不能同时真）：**LLM 裁判只做分类**（`rumor` / `side_worldline` / `unresolved`），输出 advisory、写进旁支条目的 `classification` 字段，**不改正典值**。
- 拒绝全 LLM 裁判（数值/定序不可逐条回算，违反"故事归 AI 账归代码"）；拒绝全规则引擎压"未决"（叙事矛盾一律未决会让缺席简报退化，轻分类成本低、应保留）。
- 拒绝多数投票（2–6 人异步下"多数"不解决"谁是正典"——先提交者规则已解决；且多数投票需人类同步，违反异步优先）。

**旁支账本条目形态**（`canon:false` 侧的账本 partition）：

```jsonc
{
  "seq": 4821, "ts": "...", "actor": "role_B",
  "action": { "...": "..." },
  "canon": false,
  "reason_code": "worldbook_conflict | concurrent_override | out_of_rule",
  "classification": "rumor | side_worldline | unresolved",   // LLM advisory，仅叙事矛盾时填
  "supersedes_ref": 4801,   // 指向被覆盖的那条正典 entry 的 seq
  "related_parties": ["role_B", "role_C"],
  "rumor_injection": { "target": "缺席/相关方", "perspective": "角色内", "blur_level": "由 005 定" }
}
```

正典路径保持先提交者；旁支是并行 partition，缺席简报生成器（005）与传闻注入读它。

## Q5 面板呈现 + 机制载体（票面必答：引擎输出不可被叙事层随意覆盖）

- **面板呈现**：主源 canon 值走正常面板层；争议值（`canon:false`）**只进传闻层**（模糊化/标"不确定"）。账本里双值都在（审计可回看），面板按层裁剪——避免玩家误把争议值当正典（三层裁剪实现见 [006 § Q2](./006-面板契约三层.md)）。
- **机制载体（三选叠加，不选读写锁）**：
  1. **单一结算写者**：结算执行器是唯一写"已结算值" partition 的写者；叙事提议走独立 proposals partition。面板**只从结算 partition 派生**，绝不从 proposals 派生 → 叙事层物理上无路径写进已结算值。
  2. **schema 只读版本快照**：结算读 schema 的不可变版本快照（对齐 003 Q5a 状态投影）；schema 演化不回改已结算条目。
  3. **不选读写锁**：本系统"异步优先 + 单一结算写者"下，结构性分区已解决覆盖问题；读写锁是运行态并发控制，只增复杂度无新收益。

## Q6 S2 逃生门开启条件（004 这一半，与 007 共同收口）

S2（LLM 生成可执行代码 + 沙箱执行）是**属性级逃生门，默认关**。开启需**同时**满足：

1. 该属性的结算逻辑**确实用 6 基元表达不了**（需复杂迭代/递归/外部查表——是声明式真的表达不了，不是偷懒）；
2. 007 判该属性**可量化密度高**（值得上引擎）——密度量化见 [007 § Q4](./007-自动校准与漂移纠偏.md#q4-自适应严格度密度复用-003-识别信号--3-档曲线零-token)；
3. 沙箱产物仍写**同一账本**（对齐 002 决议②，可追溯、旁支标注不失效）。

拒绝"任何玩家/GM 手动开"（= 人工调参/审核，违反硬约束）；拒绝"全关"（把"6 基元表达不了但确实要量化"的属性逼回自然语言，丢数值权威性）。条件①②由本票定，门控③的密度由 007 定，两票共同收口。

## 放弃项（本票明确不做的方向，供 /implement 不越界参考）

- 全 LLM 裁判（数值/定序不可逐条回算，违反"故事归 AI 账归代码"）；
- 全规则引擎压"未决"（叙事矛盾一律未决会让缺席简报退化）；
- 多数投票（2–6 人异步下不解决"谁是正典"，且需人类同步违反异步优先）；
- 读写锁（结构性分区已解决覆盖问题，锁只增复杂度无新收益）。
