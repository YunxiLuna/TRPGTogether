# 005 · 信息不对称：已知集、事实分级与长程检索

> **来源**：[GitHub #6 解法评论](https://github.com/YunxiLuna/TRPGTogether/issues/6)（方式：grilling 1 轮，4 题全按推荐拍板）。
>
> **为什么（人类可读）**：本票攻坚简报 F 题——"每个角色知道什么"到底怎么存、怎么算、怎么随几十次会话不漂移。核心设计=**账本事件带传播半径（propagation_radius）作为"谁知道什么"的事实源，物化视图 KnownSet[role] 增量派生**，不逐角色手存（避免 6 角色×N 事实的 O(N×角色) 存储与一致性地狱）。事实分级的自动化信号=世界书依据为主 + 引擎回算通过为量化硬门槛，玩家共识不进自动判定（异步要人类同步=违反异步优先）。谣言的模糊度 blur_level 是**事件分类的函数**（不靠 LLM 自由裁量，可审计可复现）。

## Q1 数据结构 — 每个角色知道什么（三选一 + 细化）

- 选（c）账本事件带传播半径为主 +（b）事实 who_can_see 标注为辅，**物化视图** KnownSet[role]。
- **不逐角色手存**（O(N×角色) 存储与一致性地狱、违背 append-only 单一事实源）；也不纯靠 LLM 在叙事时"现场推断该角色该知道什么"（把一致性判断放进不可复现/不可回算的 LLM，违背"故事归 AI 账归代码"）。
- 机制：账本 append-only，事件带 `propagation_radius`（谁在场/被通报，"谁知道什么"的事实源）；事实带 `who_can_see` 静态受众标注；物化视图 **KnownSet[role] = ∪(传播半径∋role 的事件) ∪ (who_can_see∋role 的事实)**，缓存、随新事件增量刷。

**数据形态**：

```jsonc
// 账本事件
{ "seq": 4801, "ts": "...", "actor": "role_A",
  "kind": "action | fact | status_transition | rumor_injection",
  "fact_ref": "f_1024", "value": 34,
  "canon_status": "canon | provisional | rejected",
  "worldbook_citation": { "section": "...", "para_hash": "...", "prefix": "…50字…" },  // 003 Q3 三级锚
  "propagation_radius": ["role_A", "role_B", "role_C"],
  "cause_ref": "seq 4790" }
// 事实条目
{ "fact_id": "f_1024", "subject": "role_A.铁剑", "value": 34,
  "canon_status": "canon", "who_can_see": ["role_A", "role_B", "role_C"],
  "worldbook_citation": { "…": "…" }, "derived_from": ["seq 4801"] }
// 派生 KnownSet（物化，非账本）
{ "role_A": { "facts": [ … ], "events": [ … ] } }
// 缺席简报（派生给 target 的投影）
{ "target": "role_B", "window": [4780, 4820],
  "items": [ { "fact_ref": "f_1024", "blur_level": "none|high|max", "perspective": "角色内", "render": "…" } ] }
```

## Q2 事实分级自动化（临时/正典提升判定 + 可回滚）

- **主信号 = 世界书依据**（003 三级锚挂得上原文）；量化类事实**硬门槛 = 引擎回算通过**（004 已定引擎是结算权威，账值不可被叙事覆盖）。
- **多模型一致**仅 007 门控的**可选增强**（002 已降级非标准路径，省成本，见 [007 § Q4](./007-自动校准与漂移纠偏.md)）；**玩家共识不进自动判定**（异步要人类同步=违反异步优先，且=人工审核正典，被禁）。
- 提升/降级是**自动**判定（依据 + 回算通过），**可回滚**=账本不删不改，正典→临时/拒绝是**追加一条 status_transition 事件**（`canon_status` 字段在账本里演进，读时取该 fact 最新状态；append-only 不破，回滚=再追加一条反向 transition，原条目永存可审计）。

## Q3 长程检索（几十次会话后的相关事实检索 + 失效兜底）

- **向量检索为主**（跨几十次会话、模糊语义召回）+ **事实 ID 链接**（结构化引用，哪条事件引用哪条正典）+ **时间衰减权重**（正典恒高权重不随时间衰减、临时随时间衰减）。
- 失败兜底：检索为空时 LLM 可即兴，但强制标 `provisional`（临时）+ 记"无世界书依据"，须过 007 回算/依据门控才能晋升，**绝不静默转正典**——即兴是临时事实，不是正典。
- 检索范围限定在该角色的 KnownSet（Q1 物化视图）：保证角色"只能基于他可能知道的信息"行动，不召回半径外事实。

## Q4 谣言机制 — 缺席简报 + 模糊化程度（blur_level 取值）

- 可见性：缺席简报的可见集合 = 该缺席角色的派生 KnownSet（半径外的事拿不到，或只拿到最高模糊"道听途说"）。
- 模糊度 **blur_level 取值由本票定死（004 在此留了占位）**，为**事件分类的函数**（不靠 LLM 自由裁量，可审计可复现——同一事件两次生成模糊度相同）：

| 事件/事实分类 | blur_level | 文案效果 |
|---|---|---|
| 正典事实（canon + 有世界书依据 + 回算通过） | `none` | 直接陈述 |
| 临时事实（provisional，无依据或回算未过） | `high` | "听人说好像…" |
| 旁支/争议值（004 的 `canon:false`、`worldbook_conflict`） | `max` | "据说…也可能是…" |

## 场景走查（本条机制可落地验证）

> B 知道"秘库钥匙藏在 X 处"（who_can_see=[B]）；C 知道"守卫巡逻子时"（propagation_radius=[C]）；A（第三人）去问 NPC"秘库怎么进？"
>
> - 系统查 A 的 KnownSet：钥匙（B 私有）∉A；巡逻（C 半径外）∉A → 答案里 A 只能基于"自己知道的东西"回答，**不泄露 B/C 的私有与半径外事**。
> - 剧情需要 A 得知：走一条**传播事件**（如 B 当众提到"有人在找秘库钥匙"→ propagation_radius=[A,B,…]）→ A 的 KnownSet 增量更新，A 拿到的是**模糊版**（未提"在哪"，X 处仍是 B 私有）。
> - A 对该 NPC 的行为/问答始终限定在 A 的 KnownSet 内；完全不在 A 半径里的事系统不注入。

## 放弃项（本票明确不做的方向，供 /implement 不越界参考）

- 玩家共识进自动判定（需人类同步，违反异步优先，且=人工审核正典，被禁）；
- 多模型一致作标准路径（002 已降级为 007 门控的可选增强）；
- 逐角色手存 KnownSet（O(N×角色) 存储与一致性地狱、违背 append-only 单一事实源）；
- LLM 在叙事时现场推断该角色该知道什么（把一致性判断放进不可复现/不可回算的 LLM，违背"故事归 AI 账归代码"）；
- blur_level 由 LLM 自由裁量（不可审计不可复现，本票改为事件分类的函数）。

## 下游影响

- 006（面板契约）：面板三层=公开层（KnownSet 内且公开）/私有层（who_can_see∋该角色）/传闻层（blur_level>none 的注入，接 004 的 `canon:false` 争议值折叠进传闻层）。
- 007（自动校准）：承接"多模型一致门控 + 即兴物晋升门控 + blur_level 作可观测指标（争议值密度、即兴物占比）"。
- 008（MVP）：故意不做多模型交叉（Q2②）与玩家共识（Q2④）。
- 009（自我批判）：须答"信息不对称漏看"风险——KnownSet 物化视图增量刷 bug 会把半径外事泄露（缓解=派生视图可重算、账本是事实源，见 [009 § R2](./009-客户端与部署.md)）。
