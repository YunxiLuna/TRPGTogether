# 006 · 状态面板数据契约（公开 / 私有 / 传闻三层）

> **来源**：[GitHub #7 解法评论](https://github.com/YunxiLuna/TRPGTogether/issues/7)（方式：grilling 1 轮，5 题全按推荐拍板）。
>
> **为什么（人类可读）**：本票攻坚简报 C 题——"动态 schema 驱动的个人状态面板如何设计，含信息不对称分层"。核心设计=**服务端下发已裁剪的 panel_view（值在服务端算好，客户端纯渲染零逻辑）**，客户端拿不到也造不出私有值（不在裁剪结果里、内存中不存在、无写路径进账本）；传闻层防看破靠 **blur 值域收窄**（high 给"涨了"不给量、max 连方向都模糊化），不是打码。三层=public / private / rumor，#5 的 `canon:false` 争议值同进传闻层，不另设第四层。

## Q1 渲染机制 + 信息不对称安全边界（三层怎么下发）

- **服务端下发已裁剪的 panel_view**（值在服务端算好，客户端纯渲染零逻辑），附带该角色能看见的 **schema 可见子集**（003 的 `citations` 三级锚、量纲、unit、range/cap）。放弃"全量 schema+全量值下发、客户端按权限裁剪"（私有值进客户端内存即泄漏，开发者工具一敲就看见，安全边界不可靠）。
- **安全边界（信息不对称靠结构不靠运行时守卫）**：客户端拿不到也造不出私有值——私有值不在裁剪结果里、客户端内存中不存在、无路径写进账本（004 已定唯一结算写者是服务端引擎）。传闻层防"看破"靠 **blur 值域收窄**（high 给"涨了"不给量，max 连方向都模糊化），不是打码；真实值只在 owner private 层与 GM 全量层，传闻文案由服务端按 blur_level 生成、客户端拿到即终态。
- 客户端渲染 = 三层 panel_view 驱动 + schema 可见子集做布局/量纲/依据角标，零结算逻辑（纯渲染，002 引擎在服务器侧）。

## Q2 三层数据契约（本票核心交付）

```jsonc
// public 层（全服可见）
{ "panel_layer": "public", "field": "hp", "value": 87, "unit": "点",
  "schema_version": "s_14", "unit_of_measure": "hp",
  "worldbook_citation": { "section": "卷2·1.1", "para_hash": "…", "prefix": "…" },
  "as_of_seq": 5210 }
// private 层（owner 本人）
{ "panel_layer": "private", "field": "sword_intent", "value": 34, "unit": "点",
  "owner_role": "role_B", "schema_version": "s_14", "as_of_seq": 5210 }
// rumor 层（blur_level>none 的注入，含 004 canon:false 争议值）
{ "panel_layer": "rumor", "field": "sword_intent",
  "description": "据说他剑意有所长进", "blur_level": "high",
  "schema_version": "s_14", "as_of_seq": 5210 }
// 注：004 的 canon:false 争议值（如「铁剑 10 vs 15」）同进传闻层，不另设第四层：
// { "panel_layer":"rumor","field":"iron_sword","description":"有人说是10，也有人说15","blur_level":"max" }
```

- **public**：该角色"公开"的状态，全服任何人面板都含；值域完整，带三级锚依据角标。
- **private**：仅 owner 角色面板含此条（他角面板该字段整体缺失，不留占位——"不占位"本身就是防看破的一环，占位暗示存在=泄漏信息量）。
- **rumor**：`blur_level`>none 的注入条目（005 Q4 分类函数）；**004 的 `canon:false` 争议值（铁剑 10 vs 15）同进传闻层，不另设第四层**——"不确定"在叙事语义上就是传闻，多设一层只增渲染复杂度。
- **三层走查（「剑意值」）**：
  - public：`剑意值 34` 全服可见（白底正常值）；
  - private：owner 面板 `剑意值 34`（锁定图标 + 灰边，仅本人）；
  - rumor：他人面板 `剑意值 "据说他剑意有所长进"`（斜体 + 淡黄色条，blur_level=high，不给具体量）。

## Q3 schema 变化时面板如何响应（版本化快照 + 增量 diff）

- 不重发全量面板：**schema 版本化快照 + 增量 diff**。003 Q5a 状态投影 + 版本标签账本条目；面板随 schema_version++ 带 `changed_fields`，客户端局部刷新；新属性升级面板自动长出新区块（带 003 三级锚依据角标，无确认无审核——003 Q5b 双门槛通过即升级，不是人工）；退化属性标 `deprecated: {merged_into: "res"} | {removed_at_seq}`（保留字段、停结算，历史值不进"活跃区块"进"历史属性"折叠区，账本结算记录时间线仍可回看，append-only 不删）。

## Q4 面板与事件账本如何保持一致（推导 vs 快照）

- **服务端物化投影快照**（panel_state[role]，账本 tail 推进时增量刷，客户端 O(1) 读 `as_of_seq` 可溯源；放弃客户端全量重放账本（几十次会话后重放成本不可控）与"混合方案"（客户端快照+自维护 schema 一致性，bug 面大）。与 003 Q5a 状态投影、004 面板只读结算 partition 同构：面板=账本派生的物化视图，崩了重放账本即可重建（append-only 事实源保证可重建性）。

## Q5 GM 视角与玩家视角是否分界面（复用 006 结论）

- **GM = 独立"世界仪表盘"**，与玩家面板物理分离（同一路由体系下独立应用/视图，009 客户端形态再细化）：全量 KnownSet 对比（005）+ 引擎调试（suspect 标签 004 例外 3、待结算队列）+ schema 演化历史（003 Q5a 版本线）+ 旁支 advisory 分类复核（004 Q4 LLM 裁判输出可人工抽查）+ 007 校准监控区。GM 可**切到某玩家视角**做"代入检查"（复用该角色的 panel_view + KnownSet，验证信息不对称没漏——这是 009 自我批判"信息不对称漏看"的人工兜底入口）。放弃"同一界面权限位"（泄漏面=无权限隔离）与"GM=第 7 角色无额外视图"（丢世界仪表盘全部用途）。

## UI 文字草图（本票交付，客户端形态见 009）

```
┌ 我的面板（role_B）───────────────────────────┐
│ [公开]  HP 87点 · 装逼值 1500 · 剑意 34点(🔒仅本人) │
│   └ 依据 ▣ 卷2·1.1「…突破成功率…」（点开原文）        │
│ [传闻]  据说他剑意有所长进…（斜体，淡黄条）           │
│   └ 传闻：有人说是铁剑10，也有人说15（深灰迷雾纹）    │
│ [历史] ▸ 历史属性（1 条，点击展开：灵气值·已合并入修为）│
└───────────────────────────────────────────────┘
GM 世界仪表盘：角色 KnownSet 矩阵 / suspect 标签 / 待结算队列 /
schema 演化时间线 / 旁支审查（advisory 分类复核）/ 007 监控区
```

- **玩家面板**（某角色视角）：顶部该角色名 + as_of_seq 时间戳；中间三栏=「公开」（白底正常值）/「私有」（锁定图标+灰边，仅本人）/「传闻」（斜体+迷雾图标+色条：none 无色 / high 淡黄 / max 深灰迷雾纹理）；每个字段右上依据角标（三级锚：章节 + 原文前 50 字悬停展开）；底部时间线（结算事件流，接 009 可视化）。
- **GM 世界仪表盘**：左侧角色 KnownSet 矩阵（谁知道什么，绿/灰）；中间引擎状态（suspect 标签列表、待结算队列、007 监控区）；右侧 schema 演化时间线 + 旁支 advisory 列表（可人工抽查 LLM 分类）；顶部可切某玩家视角做"代入检查"。

## 放弃项（本票明确不做的方向，供 /implement 不越界参考）

- 全量 schema + 全量值下发、客户端按权限裁剪（私有值进客户端内存即泄漏，开发者工具一敲就看见，安全边界不可靠）；
- 传闻层"打码"（只藏不裁值域，打码后玩家仍知道存在该字段且值被遮=泄漏信息量，且 blur 语义无法表达"涨了但不知道涨多少"）；
- 纯增量 diff 无快照兜底（客户端要自维护 schema 版本一致性，bug 面大）；
- 客户端全量重放账本（重放成本不可控）；
- GM 与玩家同界面权限位（泄漏面无隔离）/ GM=第 7 角色无额外视图（丢世界仪表盘全部用途）；
- 第四层面板（canon:false 争议值与传闻同义，多设一层只增渲染复杂度）。
