# 008 · MVP 裁剪：端到端链路 + 刻意不做清单

> **来源**：[GitHub #9 解法评论](https://github.com/YunxiLuna/TRPGTogether/issues/9)（方式：grilling 2 轮，八题全按推荐 + 终稿确认一轮）。
>
> **为什么（人类可读）**：本票把 002–007 的完整设计裁剪成一条**能端到端跑通的最小链路**（简报 D 节），并逐项定死"刻意不做"清单（每条带"何时补"触发条件），让 /implement 拿到明确边界不越界。设计默认输入=横切「LLM token 不宽裕」：MVP 全链 LLM 调用点保持最少——导入读切片、叙事生成、缺席简报读现成 description 字段零额外 LLM 调用。

## Q1–Q8 拍板结果（全按推荐项）

**Q1 导入格式**：只 txt+md、单文件。docx/多文件拆卷不在此版（见刻意不做#7）。

**Q2 初始 schema 生成失败行为**：该 schema 版本标 suspect（004 例外模式 3），游戏照常开局，结算输出带 suspect 标签下游不静默信任。理由：代码路径与 004 完全一致，且失败可观测（进 GM 调试队列），比整体静默退化为纯自然语言开局更容易被察觉——静默退化等于 MVP 里 schema 生成功能形同虚设。

**Q3 回算无已知样例时**：该属性跳过回算阶段、只做自洽检查即可进游戏，标记「未经验证」不影响开局；等剧情里真的出现可回算的机会（007 回归语料=该角色 KnownSet 内叙事历史事件）再补验。理由：自洽（内部无矛盾）≠正确（和世界书一致），但缺样例时没有更好的零人工校验手段；「没有算例就整体不开局」会卡死大量真实世界书（多数没有显式算例），违背「任意世界书可用」核心卖点。

**Q4 节奏**：自由节奏（每人随时提交行动提议，引擎按账本 seq 全局定序结算，无「回合」概念）。与 004 账本层仲裁（先提交正典/后提交旁支）完全同构，不需要额外发明「轮到谁」机制；节奏预算（007 Q1）本来就是按时间/叙事推进而非按回合数算。软回合制（可选「每 N 事件为一幕」标签）对 2 人小局意义有限，砍掉。

**Q5 字段裁剪**：005 已定字段集（`seq/ts/actor/kind/fact_ref/value/canon_status/worldbook_citation/propagation_radius/cause_ref`）**全部保留，不砍**。这套字段是各前票反复推敲过的最小闭环，砍 propagation_radius=砍掉信息不对称事实源（MVP 验不了 005 核心场景），砍 worldbook_citation=砍掉 003 三级锚可追溯性，砍 cause_ref=破坏 003 验证流水线与 007 漂移监控依赖。

**Q6 面板层数**：三层全做（public+private+rumor），rumor 层只做 none 和 max 二值（复用 006 已定 MVP 二值裁剪，high 留完整版）。理由：三层全做才能验 004 的「canon:false 争议值进传闻层」机制（铁剑 10 vs 15 场景），砍掉 rumor 层=砍掉产品最大差异化点。

**Q7 缺席简报**：必须做，但按 005 已定最小口径实现——读 rumor 条目 `description` 字段渲染，blur_level 复用 005 分类函数，零额外 LLM 调用（005 已把这条的 LLM 成本定到零）。2 人局必有「一人掉线/隔了才回来看」场景，缺席简报是异步跑团核心体验，不属于可砍项。

**Q8 验收素材**：修仙大千（`data/input` 参考 B，体系型、可量化密度高、自带「突破成功率」显式公式+上限，003 已定死为明确体系示例，完整 YAML 见 [schema-示例.md 示例 1](./schema-示例.md#示例-1--修仙突破成功率来自世界书明确体系)）。用它验收=直接验 003 已定死示例，一条链路复用；气运反例（参考 A 斗罗，[schema-示例.md 示例 3](./schema-示例.md#示例-3--气运反例保持自然语言档位不建-int-列)）不进 MVP 主验收脚本，可后续单独补验。

## 刻意不做清单（每条带「何时补」触发条件）

1. **GM 世界仪表盘（006 全量页）**：MVP 不建独立 GM 页，但保留「代入检查」的原始数据接口（panel_state 全量读能力）——触发条件：玩家数 > 2 或有人实际要当 GM 时补。
2. **S2 逃生门开启路径（002/004 Q6）**：MVP 只实现默认关（无任何属性开沙箱）——触发条件：出现真实属性被 6 基元确认表达不了、且 007 判可量化密度高档时补。
3. **多模型交叉验证（002 放弃项）**：MVP 不做——触发条件：某世界书「同量纲多处定义冲突率」超阈值（007 密度高档 + 冲突率可观测量，由 007 Q4 曲线定）且单模型生成质量不够时补。
4. **漂移自动纠偏四动作之 LLM 注入叙事（007 Q3④）**：MVP 保留 ①②③（拒绝/回退/GM 告警，全零 token），④（LLM 生成「世界在修正自身」叙事）后置——触发条件：玩家实际遇到 drift_alert 且需要「剧情内解释回退」体验时补（非冷启动必须）。
5. **KnownSet/panel_state 物化视图全量重算兜底入口（008 落地雾）**：MVP 保留账本 seq 推进即增量刷（O(1)），不建全量重算兜底——触发条件：出现物化视图刷漏/刷错的实际 bug 或回归测试失败时补。
6. **6 基元精确 YAML 文法 / 确定性启发式 token 规则全量清单（map 两条雾）**：MVP 直接定死最小可用子集（够修仙大千验收场景即可），不写全量 DSL 文法文档——触发条件：需要接入第二份真实世界书（如斗罗）或新量纲类型时补全文法。
7. **docx / 多文件导入（Q1 选 a 的放弃面）**：MVP 只 txt+md 单文件——触发条件：真实用户要导入现有 docx 世界书时补。
8. **缺席简报的「引擎裁剪字段生成新文案模板」（Q7 最小口径的放弃面）**：MVP 只读现成 description 字段渲染，不生成新文案模板——触发条件：玩家反馈简报信息量不够（如只有字段值、没有一句自然语言描述）时补模板。
9. **007 漂移监控 W/N/k 具体取值与 3 档曲线全场景通用系数（map 雾）**：MVP 用修仙大千验收场景实测调出一组能跑通的初值，不定「全场景通用」公式——触发条件：接入密度明显不同的第二份世界书时补通用曲线。

## 验收标准（最小场景脚本）

- **素材**：`data/input` 修仙大千（转成 md 供导入，因为 Q1 只收 txt/md）。
- **场景**：2 名玩家（角色 A、B），围绕「突破成功率」体系：A 提交一次突破行动提议（带丹药基础成功率+是否强行突破），B 在 A 未回看期间提交一次矛盾/相关行动（如 B 也用了同一颗丹药，触发 004 账本层先提交正典/后提交旁支仲裁），B 缺席期间 A 的缺席简报读到 B 相关事件的 rumor description（Q7）。
- **验证点**：
  1. 003 修仙突破成功率 schema（formula+quantity(cap)+state_machine）生成并通过自洽+回算（Q3，有已知算例可用）；
  2. A/B 各自 panel_view 三层（public/private/rumor 二值）正确裁剪、私有字段他不留占位（Q6）；
  3. 账本 seq 全局定序正确（Q4 自由节奏）；
  4. 铁剑 10 vs 15 类型的 canon:false 争议值正确进 rumor 层、blur_level=max（Q6）；
  5. B 缺席简报读到 A 相关事件的正确 blur_level 文案（Q7）。

## 放弃项汇总（本票明确不做的方向，供 /implement 不越界参考）

GM 世界仪表盘页、S2 逃生门开启路径、多模型交叉验证、LLM 注入叙事纠偏、物化视图全量重算兜底入口、全量 DSL 文法文档、docx/多文件导入、缺席简报新文案模板、全场景通用 W/N/k 曲线系数。
