## 两层漏斗走查（示例 1 / 2 / 3 共用的识别→起草流程）

1. **第一层 确定性启发式定位（不用 LLM）**：token 规则扫候选区——等号/上限 token、稳定列头伪表格、一行色阶链、`x/N` 计数。便宜、可复现、不引入 LLM 找漏。
2. **第二层 LLM 解读**：定位出的区域，起草 schema 并打置信度。
3. 置信度 = 结构信号强度 × 语义消费度 × 定义一致性（判据见 [003 § Q1](./003-schema-子系统.md#q1-识别信号机制与阈值两层漏斗--三档置信度)）：
   - 结构：显式公式 > 稳定列头伪表 > 藏在叙事里的计数/状态机。
   - 消费度：被"规则/公式实际消费"才算高（气运±5%、悟性每 50 点 +1%）；仅被"叙事提及"或无消费公式=低（魅力 1~100 无 +X% 规则吃它）。
   - 一致性：同量多处定义且用词一致=高；重复且矛盾（魂环色 3.3 vs 15.2）=降档。
4. 三档阈值：高置信→自动建；中置信→建但标"低置信/需回算"；低置信（纯叙事或无消费公式）→不建，保持自然语言。

## 示例 1 — 修仙突破成功率（来自世界书明确体系）

**两层漏斗走查**：
- 第一层 token 规则命中"第三卷·4.3 突破成功率=丹药基础+强行加成×50%、上限 15%/95%"——等号 + 上限 token + 百分比区间，**显式公式=最强结构信号**。
- 第二层 LLM 解读：`quantity{突破成功率}` + `formula`（丹药基础 + 强行加成×50%，cap 15%/95%）+ `state_machine`（三路径突破 + 4 级失败终态：圆满突破/小幅突破/失败/重伤）。
- 置信度：结构=高（显式公式）；消费度=高（被"突破行动"规则消费，是结果量）；一致性=高（单一卷定义）。→ **高置信，自动建**。

**YAML**（6 基元原样抄）：

```yaml
quantity:
  突破成功率:
    unit: percent
    range: { min: 0, max: 100 }
    cap: { floor: 15, ceiling: 95 }   # 第三卷·4.3 上限
    citations:
      - { section: "第三卷·4.3", para_hash: "8f3a…", prefix: "突破成功率=丹药基础+强行加成×50%，上限15%…" }

formula:
  突破成功率: "丹药基础 + 强行加成 * 0.5"
  cap: { floor: 15, ceiling: 95 }

state_machine:
  突破:
    states: [未突破, 圆满突破, 小幅突破, 失败, 重伤]
    transitions:
      - { from: 未突破, to: 圆满突破, guard: "成功率>=阈值_high", probability: "成功率" }
      - { from: 未突破, to: 小幅突破, guard: "成功率>=阈值_mid", probability: "成功率" }
      - { from: 未突破, to: 失败,     guard: "默认",          probability: "1-成功率" }
      - { from: 未突破, to: 重伤,     guard: "强行突破且失败", probability: "强行加成*0.2" }
```

**回算断言**（003 Q4 回算段，MVP 验收必做）：世界书第三卷·4.3 自带已知算例（丹药基础 30% + 强行加成 20% → 总成功率 = 30 + 20×50% = 40%，cap 区间内 [15,95]），引擎重算结果须 = 40%（误差带随 007 Q4 密度曲线缩放）。

## 示例 2 — 剑意值（剧情增量生成）

**两层漏斗走查**：
- 第一层 token 规则：初期剧情里"剑意值"无等号/上限 token（玩家自创属性，世界书未定义）→ 第一层不命中，保持自然语言。
- 后续剧情出现"剑意值超过 50 才能使出破山式"——**双门槛升级判定触发**（003 Q5b）：①被至少一条产生量化结果的公式/规则实际消费（"超过 50 才能用破山式"）②剧情已确认它是承重量（非路过形容，连续 N 轮被引用，N 与权重由 007 定）。
- 第二层 LLM 解读：建 `quantity{剑意值}` + `formula`（消费它的那条规则，局部增量只动这一个属性+它的消费规则）。

**YAML**（6 基元原样抄，局部增量）：

```yaml
quantity:
  剑意值:
    unit: point
    range: { min: 0, max: 100 }
    cap: 50            # "破山式"门槛（剧情确认的承重量；具体取值随剧情而定，本示例取 50 仅为演示形态）
    citations:
      - { section: "剧情·第 N 幕", para_hash: "<归一化段落短哈希>", prefix: "剑意值超过…才能使出破山式…" }

formula:
  破山式解锁: "剑意值 >= <门槛值>"   # 示例：消费剑意值的那条规则（形态演示，门槛值随剧情定）
```

**升级判定走查**（双门槛，003 Q5b）：
- 门槛①"被公式消费"：✓（"剑意值超过 50 才能用破山式"）
- 门槛②"剧情承重量"：连续 N 轮被叙事引用/结算消费（**N 与权重由 007 定，本文件不臆造具体数值**）——剧情里剑意值在多幕被引用达到 N 次 → **满足双门槛，升级为 schema**。
- 若剧情只提 1 次"剑意值挺高的"（无消费公式+承重量不够）→ **不升级，保持自然语言**。

## 示例 3 — 气运（反例：保持自然语言档位，不建 int 列）

**两层漏斗走查**：
- 第一层 token 规则：气运有"1~100"数值壳（区间 token 命中）→ 第一层定位出候选区。
- 第二层 LLM 解读：气运的实际消费是"±5%/翻倍档位语义"（"气运高时，所有成功率 +5%"），**无精算整数消费**（不是"气运值 80"参与公式计算，是"气运高/中/低"档位触发 ±5%/翻倍）。
- 置信度：结构=中（有区间 token 但无等号/上限公式）；消费度=**低**（被叙事提及档位，非被规则/公式精算消费——判据：被"规则/公式消费"才算高，被"叙事提及"不算）；一致性=高（单一定义）。→ **中/低置信，不建 int 列**。

**保持自然语言档位**（不建 quantity，存 narrative_role 或 高/中/低 枚举）：

```yaml
# 气运不建 quantity，存为 narrative_role 档位（6 基元里 mapping 仅用于档位→模糊描述映射）
quantity:
  气运:
    # 刻意不建 int 列；用 mapping 存档位→模糊语义（非精算数值）
    values: [高, 中, 低]            # enum 档位，非 int
    narrative_role: "luck"
    citations:
      - { section: "第一卷·2.1", para_hash: "7d2e…", prefix: "气运高者，诸事顺遂，成功率+5%…" }

mapping:
  气运:
    高: { effect: "所有成功率 +5%（模糊档位，非精算）" }
    中: { effect: "无修正" }
    低: { effect: "所有成功率 -5%（模糊档位，非精算）" }
```

**为什么不算 schema 膨胀**：气运"保持自然语言档位"是 003 Q2 的**反例**——有数值壳但无消费公式的属性，建 int 列=把档位语义扭成精算数值（"气运 80"没有意义，只有"气运高/中/低"有），正确做法=存枚举档位 + narrative_role，不进 6 基元 quantity 的精算路径。这是 002"防 schema 变牢笼"第一道闸（固定 6 基元）+ 003 Q1 消费度判据（被叙事提及不算消费）的落地示范。
